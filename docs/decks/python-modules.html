What is a Module?

MODULE

●A module is simply a .py file containing Python code — functions, variables and classes

●Modules let you organise code into separate, reusable files

●Python ships with many built-in modules ready to use, like math and random

●Once imported, everything inside a module becomes available in your program

import math

print(math.pi)

Output

3.141592653589793

Why Use Modules?

WHY?

●Avoid rewriting the same code — reuse tested, ready-made functions

●Keep large programs organised into smaller, logical files

●Reduce naming conflicts by grouping related names inside a module's own namespace

●You can also create and import your own custom modules

import math

print(math.sqrt(16))

Output

4.0

import

The from...import Statement

from...import

●from module import name brings just ONE name directly into your program

●No module prefix needed afterward — use sqrt() instead of math.sqrt()

●Several names can be imported at once: from math import pi, sqrt

●Only the imported names are available — the rest of the module stays hidden

from math import sqrt, pi

print(sqrt(16))

print(pi)

Output

4.0

3.141592653589793

Tricky: from...import Gotchas

GOTCHA

Importing names directly comes with its own risks:

from math import sqrt

print(math.pi)

✗  NameError

from...import only brings in the names you asked for — math itself is never defined.

pi = "custom"

from math import pi

print(pi)

→  3.141592653589793

An imported name silently overwrites any existing variable with the same name.

from math import *

print(sqrt(9), floor(4.7))

→  3.0 4

The * imports EVERY public name — convenient, but risks overwriting your own names.

import math vs from math import sqrt

import/from

Two ways to bring in the same function — different trade-offs:

import math

import math

print(math.sqrt(9))

→  3.0

Keeps every name inside math's own namespace — safer, but needs the prefix every time.

from math import sqrt

from math import sqrt

print(sqrt(9))

→  3.0

Shorter to type, but ONLY sqrt is available — math.pi would still raise a NameError.

Tricky: Using Constants Correctly

GOTCHA

Constants are values — treat them like any other number:

import math

print(math.pi())

✗  TypeError

pi is a value, not a function — calling it with ( ) always fails.

import math

radius = 5

import math

print(round(math.pi, 2))

→  3.14

Combine math.pi with the built-in round() to control decimal places.

GOTCHA

import math

Tricky: ceil()/floor() with Negative Numbers

GOTCHA

“Up” and “down” mean toward infinity, not toward zero:

import math

print(math.ceil(-4.2))

→  -4

Rounding UP means toward positive infinity — -4 is greater than -4.2.

import math

print(math.floor(-4.2))

→  -5

Rounding DOWN means toward negative infinity — -5 is less than -4.2.

import math

print(math.ceil(5.0))

→  5

A whole number stays exactly the same — ceil() and floor() never change it.

Tricky: Trig Functions Use Radians

GOTCHA

The single most common mistake with this whole function group:

import math

print(math.sin(90))

→  0.8939966636005579

90 here means 90 RADIANS, not degrees — not remotely equal to sin(90°).

import math

angle = math.radians(90)

print(math.sin(angle))

→  1.0

Convert degrees to radians first with math.radians() to get the expected result.

import math

print(round(math.tan(math.pi / 4), 2))

→  1.0

π/4 radians is exactly 45°, where tan() equals 1.

Tricky: randint() Inclusive Bounds

GOTCHA

Both ends of the range are genuinely reachable:

import random

x = random.randint(1, 3)

print(x in [1, 2, 3])

→  True

randint(1, 3) can produce 1, 2, OR 3 — both ends are included.

import random

print(random.randint(5, 5))

→  5

When both arguments are equal, the “random” result is always that same value.

import random

random.randint(5, 1)

✗  ValueError

The first argument must be ≤ the second, or it raises an error.

The random.randrange() Function

randrange()

●random.randrange(stop) picks a random integer from 0 up to (but NOT including) stop

●random.randrange(start, stop) picks from start up to (but NOT including) stop

●A third argument sets a step, just like range(): randrange(0, 10, 2)

●Behaves like a random pick from range(...), rather than always including the stop value

import random

x = random.randrange(5)

y = random.randrange(2, 10, 2)

print(x in [0,1,2,3,4])

print(y in [2,4,6,8])

Output

True

True

randint() vs randrange()

randint/randrange

Both pick a random int — but the upper bound behaves differently:

randint()

import random

x = random.randint(1, 10)

print(1 <= x <= 10)

→  True

The upper bound IS included — 10 is a possible result.

randrange()

import random

x = random.randrange(1, 10)

print(x in range(1, 10))

→  True

The upper bound is EXCLUDED, just like range() — 10 can never appear.

Tricky: median() with Even-Length Data

GOTCHA

An even number of values changes how the median is found:

import statistics

data = [10, 20, 30, 40]

print(statistics.median(data))

→  25.0

With an EVEN number of values, median() averages the two middle numbers.

import statistics

data = [40, 10, 30, 20]

→  25.0

The list doesn't need to be sorted first — median() handles that internally.

import statistics

print(statistics.median([5]))

→  5

A single-element list simply returns that one value.

Tricky: mode() Gotchas

GOTCHA

Ties and empty data both need special care:

import statistics

data = [1, 1, 2, 2, 3]

print(statistics.mode(data))

→  1

With a tie, mode() returns whichever value appears FIRST in the data.

import statistics

print(statistics.mode([1, 2, 3]))

→  1

With no repeats at all, mode() simply returns the first value it sees.

import statistics

print(statistics.mode([]))

✗  StatisticsError

An empty sequence has no mode at all — calling it raises an error.

Rapid Fire: Common Exam Traps

TRAPS

Four one-liners that trip up almost every class — read carefully:

import math

print(math.floor(7))

→  7

floor() on an already-whole number just returns it unchanged, as an int.

from math import sqrt

print(math.sqrt(4))

✗  NameError

from...import never defines the module name itself — only the names you explicitly imported.

import random

print(type(random.random()))

→  <class 'float'>

random.random() always returns a float, never an int.

import statistics

print(statistics.mean([2, 4]))

→  3

The mean of two numbers is just their average — here exactly a whole number.
