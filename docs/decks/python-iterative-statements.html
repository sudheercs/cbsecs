Why Do We Need Loops?

WHY?

●A loop repeats a block of code multiple times without rewriting it

●Useful whenever the same action must happen for every item, or until a condition changes

●Without loops, printing "Hello" 100 times would need 100 separate print() statements

●Python provides two kinds of loops: for and while

Tricky: for Loop Gotchas

GOTCHA

Small syntax slips that are easy to make early on:

for i in range(3)

    print(i)

✗  SyntaxError

The colon : at the end of the for line is mandatory — it's easy to forget.

for i in range(3):

print(i)

✗  IndentationError

The loop body MUST be indented — Python uses indentation to know what's inside the loop.

for i in range(3):

    pass

print(i)

→  2

The loop variable still exists after the loop ends, holding its LAST value.

The range() Function

range()

●range(stop) generates numbers from 0 up to (but not including) stop

●range(start, stop) generates numbers from start up to (but not including) stop

●range(start, stop, step) adds a custom step size, which can be negative

●range() doesn't create a list in memory — it generates numbers on demand

print(list(range(5)))

print(list(range(2, 8)))

Output

[0, 1, 2, 3, 4]

[2, 3, 4, 5, 6, 7]

Tricky: range() Gotchas

GOTCHA

range() has a few boundary rules worth memorising:

print(list(range(5, 5)))

→  []

When start equals stop, range() produces nothing at all — an empty sequence, not an error.

print(list(range(10, 0, -2)))

→  [10, 8, 6, 4, 2]

A negative step counts DOWNWARD — start must be greater than stop for this to work.

print(list(range(1, 10))[-1])

→  9

The stop value is always excluded — range(1, 10) stops at 9, not 10.

Tricky: while Loop Gotchas

GOTCHA

The single biggest risk with while loops:

i = 1

while i <= 3:

    print(i)

✗  Runs forever

Forgetting to update i inside the loop means the condition NEVER becomes False — an infinite loop.

i = 5

while i <= 3:

    print(i)

→  (nothing printed)

If the condition is False right away, the loop body never runs — not even once.

i = 0

while i < 3:

    i += 1

print(i)

→  3

After the loop ends, i holds the first value that made the condition False.

for Loop vs while Loop

for / while

Two loops, two different jobs:

for loop

for i in range(5):

    print(i)

→  0 1 2 3 4

Best when you know exactly how many times to repeat, or are working through a sequence.

while loop

i = 0

while i < 5:

    print(i)

    i += 1

→  0 1 2 3 4

Best when repetition depends on a CONDITION, and the count isn't known in advance.

Tricky: break Gotchas

GOTCHA

break is more limited in scope than students expect:

for i in range(3):

    for j in range(3):

        if j == 1:

            break

        print(i, j)

→  0 0

1 0

2 0

break only exits the INNERMOST loop it's inside — the outer loop keeps running.

i = 0

while True:

    if i == 2:

        break

    print(i)

    i += 1

→  0

1

while True: combined with break is a common way to write a loop that exits partway through.

for i in range(5):

    if i == 10:

        break

    print(i)

→  0 1 2 3 4

If the break condition never becomes True, the loop simply finishes normally.

break vs continue

break/continue

Both react to a condition mid-loop — with very different results:

break

for i in range(5):

    if i == 3:

        break

    print(i)

→  0 1 2

Exits the loop completely — nothing after i == 3 ever runs.

continue

for i in range(5):

    if i == 3:

        continue

    print(i)

→  0 1 2 4

Skips ONLY i == 3 — the loop keeps going for every other value.

Nested Loops

NESTED

●A nested loop is a loop written inside the body of another loop

●The inner loop completes ALL of its iterations for every single iteration of the outer loop

●Commonly used for grids, tables, and — as we'll see next — printing patterns

●Any combination of for and while loops can be nested together

for i in range(2):

    for j in range(3):

        print(i, j)

Output

0 0

0 1

0 2

1 0

1 1

1 2

Tricky: Nested Loop Gotchas

GOTCHA

The outer and inner loops are more independent than they look:

total = 0

for i in range(3):

    for j in range(3):

        total += 1

print(total)

→  9

The inner loop runs 3 times for EACH of the outer loop's 3 passes — 3 × 3 = 9 total.

for i in range(3):

    for j in range(3):

        if j == 1:

            break

print("done")

→  done

break inside the inner loop never affects the outer loop — it keeps running normally.

for i in range(2):

    for i in range(3):

        pass

print(i)

→  2

Reusing the same variable name in both loops is legal, but the inner loop overwrites the outer one's value.

Tricky: Pattern Printing Gotchas

GOTCHA

Nearly every pattern bug traces back to end="" or an off-by-one range:

for i in range(3):

    print("*")

→  *

*

*

Without end="", every print() starts a new line — stars never sit side by side.

for i in range(3):

    print("*", end="")

print()

→  ***

end="" removes the newline, but you still need one final print() to move on afterward.

for i in range(3):

    for j in range(i):

        print("*", end="")

    print()

→  (blank)

*

**

range(i), not range(i+1), makes row 0 print ZERO stars — an easy off-by-one mistake.

Rapid Fire: Common Exam Traps

TRAPS

Four one-liners that trip up almost every class — read carefully:

for i in range(5):

    if i == 5:

        break

    print(i, end="")

→  01234

Since i never actually reaches 5, break never triggers — all 5 numbers print normally.

for i in range(0):

    print(i)

→  (nothing)

range(0) produces no values at all, so the loop body never executes even once.

x = 5

while x > 0:

    x -= 1

print(x)

→  0

The loop keeps subtracting until the condition finally becomes False, landing exactly at 0.

for i in "abc":

    if i == "b":

        continue

    print(i, end="")

→  ac

continue skips only "b" — the loop still finishes the remaining characters.
