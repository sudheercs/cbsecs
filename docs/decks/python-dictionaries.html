Introduction to Dictionaries

type: dict

●A dictionary stores data as key:value pairs inside curly braces { }

●Each key maps to exactly one value, and keys must be unique

●Dictionaries are ordered (insertion order is preserved) and mutable

●Dictionaries belong to the built-in dict class

d = {"name": "Riya", "age": 17}

print(d)

print(type(d))

Output

{'name': 'Riya', 'age': 17}

<class 'dict'>

Creating Dictionaries

{} / dict()

●Curly braces {key: value, ...} create a dictionary directly

●dict() can build one from keyword arguments or a list of pairs

●{} (empty braces) creates an empty dictionary — NOT an empty set

●Values can repeat and be of any type; keys cannot

a = {"x": 1, "y": 2}

b = dict(x=1, y=2)

c = dict([("x", 1), ("y", 2)])

print(a == b == c)

Output

True

Tricky: Creation Traps

GOTCHA

Two surprises that catch almost everyone once:

d = {"a": 1, "a": 2}

print(d)

→  {'a': 2}

A repeated key doesn't raise an error — it silently overwrites the earlier value.

d = {}

print(type(d))

→  <class 'dict'>

Empty curly braces always make a dictionary, never a set — use set() for an empty set.

Rules for Dictionary Keys

KEY RULES

●Keys must be unique — a repeated key simply overwrites the earlier value

●Keys must be immutable (hashable): strings, numbers and tuples all work

●Lists and other dictionaries can NEVER be used as keys

●Values have no such restriction — they can be any type, including lists or dicts

d = {1: "one", (2, 3): "pair"}

print(d)

Output

{1: 'one', (2, 3): 'pair'}

Fundamentals

6 / 40

Tricky: Key Rule Traps

GOTCHA

What can — and can't — be used as a key:

d = {[1, 2]: "x"}

✗  TypeError

unhashable type: 'list' — lists (and other dicts) can never be used as keys.

d = {(1, 2): "point"}

print(d)

→  {(1, 2): 'point'}

Tuples ARE hashable, so they make perfectly valid dictionary keys.

d = {1: "int", "1": "str"}

print(d)

→  {1: 'int', '1': 'str'}

The int 1 and the string "1" are different keys — type matters.

Accessing Items Using Keys

d[key]

●Use d[key] to retrieve the value linked to that key

●Accessing a key that doesn't exist raises a KeyError immediately

●Keys are case-sensitive and type-sensitive: "Age" and "age" are different keys

●Unlike lists, dictionaries are accessed by key, never by position

d = {"name": "Riya", "age": 17}

print(d["name"])

print(d["age"])

Output

Riya

17

Fundamentals

8 / 40

Tricky: KeyError Examples

GOTCHA

Direct access [ ] is strict — no key means no mercy:

d = {"name": "Riya"}

print(d["age"])

✗  KeyError

Accessing a missing key crashes the program — there's no “safe” version of [ ].

d = {"Age": 17}

print(d["age"])

✗  KeyError

Keys are case-sensitive — "Age" and "age" are two completely different keys.

d = {1: "one"}

print(d["1"])

✗  KeyError

Keys are type-sensitive too — the int 1 and the string "1" are different keys.

The get() Method

get()

●get(key) returns the value for key, or None if the key is missing

●get(key, default) lets you supply your own fallback value instead of None

●Never raises a KeyError, no matter what key you ask for

●The safest way to read from a dictionary when a key might be missing

d = {"name": "Riya"}

print(d.get("name"))

print(d.get("age"))

print(d.get("age", 0))

Output

Riya

None

0

Accessing Data

10 / 40

d[key] vs get()

d[key] / get()

Two ways to read a value — with very different failure behaviour:

d[key]

d = {"a": 1}

print(d["b"])

✗  KeyError

Crashes the program instantly if the key is missing — use only when you're certain it exists.

get()

d = {"a": 1}

print(d.get("b", 0))

→  0

Returns a safe default instead of crashing — the recommended choice for uncertain lookups.

Mutability: Adding a New Item

ADD

●Assigning to a new key adds a brand-new key:value pair

●d[new_key] = value works even if new_key never existed before

●The dictionary grows in place — no new dictionary object is created

●New items are added at the end, preserving insertion order

d = {"name": "Riya"}

d["age"] = 17

print(d)

Output

{'name': 'Riya', 'age': 17}

Mutability

12 / 40

Mutability: Modifying an Existing Item

MODIFY

●Assigning to an EXISTING key updates its value in place

●d[key] = value works for both adding and updating — Python decides based on whether the key already exists

●The dictionary's identity, id(), stays the same after the change

●This is what makes dictionaries mutable, just like lists

d = {"name": "Riya", "age": 17}

d["age"] = 18

print(d)

Output

{'name': 'Riya', 'age': 18}

Mutability

13 / 40

Tricky: Mutability & Aliasing Traps

GOTCHA

The same aliasing rules that apply to lists apply here too:

a = {"x": 1}

b = a

b["x"] = 99

print(a)

→  {'x': 99}

b = a does NOT copy the dictionary — both names point to the same object.

def update(d):

    d["new"] = True

info = {}

update(info)

print(info)

→  {'new': True}

Dictionaries passed into a function are shared — the function can modify the caller's dict.

d = {"a": [1, 2]}

d["a"].append(3)

print(d)

→  {'a': [1, 2, 3]}

Modifying a mutable value (like a list) inside a dictionary changes it in place.

Traversing a Dictionary

for k,v in d

●for key in d: visits each key directly, in insertion order

●for key, value in d.items(): gives both the key and value together

●d.values() lets you loop over just the values, ignoring keys

●Looping over a dictionary directly is the same as looping over its keys

d = {"a": 1, "b": 2, "c": 3}

for key, value in d.items():

    print(key, value)

Output

a 1

b 2

c 3

Traversal

15 / 40

Tricky: Traversal Gotchas

GOTCHA

Reading a dictionary while looping is fine — resizing it isn't:

d = {"a": 1, "b": 2}

for k in d:

    d[k] = d[k] * 2

print(d)

→  {'a': 2, 'b': 4}

Changing VALUES for keys that already exist during a loop is perfectly safe.

d = {"a": 1}

for k in d:

    d["b"] = 2

✗  RuntimeError

Adding or removing KEYS while looping raises an error — the dict changed size mid-iteration.

d = {"b": 2, "a": 1}

print(list(d))

→  ['b', 'a']

Since Python 3.7, dictionaries always preserve insertion order — never assume sorted order.

17 / 40

Tricky: keys()/values()/items() Are Live Views

GOTCHA

These three return VIEWS, not lists — a subtle but important difference:

d = {"a": 1}

k = d.keys()

d["b"] = 2

print(k)

→  dict_keys(['a', 'b'])

keys() returns a LIVE view — it updates automatically as the dictionary changes.

d = {"a": 1, "b": 2}

print(list(d.values()))

→  [1, 2]

Wrap a view in list() to get a normal, independent list you can index or store.

d = {"a": 1}

print(type(d.keys()))

→  <class 'dict_keys'>

A view is its own type — not a list — though it supports looping and membership tests.

The update() Method

update()

●update(other_dict) merges another dictionary's key:value pairs into this one

●Matching keys get overwritten; new keys are simply added

●Can also accept keyword arguments: d.update(age=18)

●Modifies the dictionary in place and always returns None

d = {"name": "Riya", "age": 17}

d.update({"age": 18, "city": "Delhi"})

print(d)

Output

{'name': 'Riya', 'age': 18, 'city': 'Delhi'}

Methods & Functions

19 / 40

Tricky: update() Gotchas

GOTCHA

update() is more flexible than it looks:

d = {"a": 1}

result = d.update({"b": 2})

print(d, result)

→  {'a': 1, 'b': 2} None

Just like sort() for lists, update() modifies in place and always returns None.

d = {"a": 1}

d.update(a=99, c=3)

print(d)

→  {'a': 99, 'c': 3}

Keyword arguments work too — a quick way to update several keys at once.

d = {"a": 1}

d.update([("b", 2), ("c", 3)])

print(d)

→  {'a': 1, 'b': 2, 'c': 3}

update() also accepts a list of key-value pairs, not just another dictionary.

The del Statement

del

●del d[key] removes a single key:value pair from the dictionary

●del d deletes the entire dictionary variable itself

●Raises a KeyError if the key doesn't exist

●A statement, not a method — it never returns a value

d = {"a": 1, "b": 2, "c": 3}

del d["b"]

print(d)

Output

{'a': 1, 'c': 3}

The clear() Method

clear()

●clear() removes every key:value pair, leaving an empty dictionary

●The dictionary object itself still exists — it's just empty

●Different from del d, which removes the variable completely

●A quick way to reset a dictionary without creating a new one

d = {"a": 1, "b": 2}

d.clear()

del d[key] vs del d vs clear()

del / clear()

Three ways to remove data — each with a very different scope:

del d[key]

d = {"a": 1, "b": 2}

del d["a"]

print(d)

The fromkeys() Method

fromkeys()

●dict.fromkeys(iterable, value) builds a new dictionary from a sequence of keys

●Every key gets the SAME value — the second argument defaults to None

●A quick way to initialise a dictionary with a fixed set of keys

●Called on the dict class itself, not on an existing dictionary instance

keys = ["a", "b", "c"]

d = dict.fromkeys(keys, 0)

print(d)

Output

{'a': 0, 'b': 0, 'c': 0}

Methods & Functions

24 / 40

Tricky: fromkeys() Mutable Default Trap

GOTCHA

One of the most dangerous one-liners in this whole chapter:

d = dict.fromkeys(["a", "b"])

print(d)

→  {'a': None, 'b': None}

With no value given, every key defaults to None.

d = dict.fromkeys(["a", "b"], [])

d["a"].append(1)

print(d)

→  {'a': [1], 'b': [1]}

All keys share the exact SAME list object — modifying one appears to change every key!

d = {}

for k in ["a", "b"]:

    d[k] = []

d["a"].append(1)

print(d)

→  {'a': [1], 'b': []}

Building the dictionary with a loop instead avoids the shared-reference trap.

The copy() Method

copy()

●copy() returns a shallow copy — a new, independent dictionary object

●Changing the copy's top-level keys/values does NOT affect the original

●“Shallow” means nested mutable objects (like a list value) are still shared

●Equivalent to dict(d) or d.copy()

d = {"a": 1, "b": 2}

e = d.copy()

e["a"] = 99

print(d, e)

Output

{'a': 1, 'b': 2} {'a': 99, 'b': 2}

Methods & Functions

26 / 40

Tricky: Shallow Copy Gotchas

GOTCHA

“Independent copy” only goes one level deep:

d = {"a": 1}

e = d

e["a"] = 99

print(d)

→  {'a': 99}

e = d is an alias, NOT a copy — both names still point to the same dictionary.

d = {"a": 1}

e = d.copy()

e["a"] = 99

print(d)

→  {'a': 1}

copy() makes a real, independent dictionary — the original is now safe.

d = {"a": [1, 2]}

e = d.copy()

e["a"].append(3)

print(d)

→  {'a': [1, 2, 3]}

A SHALLOW copy still shares nested mutable values — the inner list is the same object in both.

The pop() Method

pop()

●pop(key) removes a key and returns its value

●pop(key, default) supplies a fallback instead of raising an error if missing

●Without a default, a missing key raises a KeyError

●The most common way to remove an item when you also need its value

d = {"a": 1, "b": 2}

x = d.pop("a")

print(d, x)

Output

{'b': 2} 1

The popitem() Method

popitem()

●popitem() removes and returns the LAST inserted key:value pair, as a tuple

●Takes no key argument — it always targets the most recently added item

●Useful for treating a dictionary like a stack of key:value pairs

●Raises a KeyError if called on an empty dictionary

d = {"a": 1, "b": 2, "c": 3}

item = d.popitem()

print(d, item)

Output

{'a': 1, 'b': 2} ('c', 3)

Removing Items

29 / 40

pop() vs popitem() vs del

pop/popitem/del

Three ways to remove — by key, by position, or as a bare statement:

pop()

d = {"a": 1, "b": 2}

x = d.pop("a")

print(d, x)

→  {'b': 2} 1

Removes by KEY and returns the value — accepts a default to avoid errors.

popitem()

d = {"a": 1, "b": 2}

item = d.popitem()

print(d, item)

→  {'a': 1} ('b', 2)

Removes the LAST inserted pair, returned as a (key, value) tuple.

del

d = {"a": 1, "b": 2}

del d["a"]

print(d)

→  {'b': 2}

A statement, not a method — removes by key but returns nothing at all.

The setdefault() Method

setdefault()

●setdefault(key, default) returns the value if key exists

●If key is missing, it INSERTS key with that default, then returns it

●Combines a get() and a conditional insert into a single step

●A genuine in-place update — the dictionary's identity stays the same

d = {"a": 1}

x = d.setdefault("a", 0)

y = d.setdefault("b", 0)

print(d, x, y)

Output

{'a': 1, 'b': 0} 1 0

Methods & Functions

31 / 40

Tricky: setdefault() in Action

GOTCHA

The classic “grouping” pattern every exam paper loves:

d = {}

d.setdefault("fruits", []).append("apple")

d.setdefault("fruits", []).append("mango")

print(d)

→  {'fruits': ['apple', 'mango']}

The list is created only on the FIRST call, then reused every time after.

d = {"a": 1}

print(d.setdefault("a", 99))

→  1

If the key already exists, the default is completely ignored — the existing value wins.

d = {}

print(d.setdefault("x"))

print(d)

→  None {'x': None}

With no default given, it falls back to None, just like get().

Methods & Functions

33 / 40

Tricky: max()/min()/sorted() Gotchas

GOTCHA

By default these three all look at the KEYS, not the values:

d = {"a": 3, "b": 1, "c": 2}

print(max(d))

→  'c'

max()/min()/sorted() operate on the KEYS by default — not on the values.

d = {"a": 3, "b": 1, "c": 2}

print(max(d, key=d.get))

→  'a'

Pass key=d.get to instead find the key with the LARGEST value.

d = {"a": 3, "b": 1, "c": 2}

print(sorted(d.items()))

→  [('a',3),('b',1),('c',2)]

sorted() on items() gives back a list of (key, value) tuples, sorted by key.

Rapid Fire: Common Exam Traps

TRAPS

Four one-liners that trip up almost every class — read carefully:

d = {"a": 1}

print("a" in d)

→  True

in on a dictionary checks the KEYS by default, never the values.

d = {"a": 1}

print(1 in d)

→  False

The value 1 is not a key — membership never looks inside the values automatically.

d = {}

print(bool(d))

→  False

An empty dictionary is falsy; any non-empty dictionary is truthy.

a = {"x": 1}

b = {"x": 1}

print(a == b, a is b)

→  True False

== compares VALUES; is compares IDENTITY — equal dicts can still be different objects.
