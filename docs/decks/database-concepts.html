What is a Database?

DATABASE

●A database is an organised collection of related data, stored so it can be easily accessed, managed and updated

●It is usually stored electronically, often on a server shared by many users

●Related data is kept together: a school database links students, teachers, classes and marks

●The software that manages a database is called a DBMS (covered shortly)

The File System Approach

FILE SYSTEM

●Before databases, data was kept in separate files — text files or spreadsheets — owned by different applications

●Each department maintained its own files, with no central control

●The same data was often stored again and again in many files

●When one copy was changed, the others were easily forgotten

Problems with the File System

PROBLEMS

Six weaknesses that led to the invention of databases:

Data Redundancy

The same data is stored repeatedly in many files, wasting storage space.

Riya's address stored in 3 separate files

Data Inconsistency

A change made in one copy but not the others leaves the copies disagreeing.

Class is 12-A in one file, 12-B in another

Difficult Data Access

Every new kind of question needs a new program to be written.

“List students from Delhi” needs custom code

Data Isolation

Data is scattered across files in different formats, so combining it is hard.

Text file in one department, spreadsheet in another

Weak Security

Hard to give different users different permissions over different data.

A clerk can open a file meant for the principal

No Integrity Rules

Rules about valid data must be re-coded in every program that uses it.

A negative age slips into one program’s file

Database Models

MODELS

A data model decides HOW the data is organised. Four common ones:

Hierarchical

Data is organised like a tree: each parent can have many children, but each child has just one parent.

e.g. an organisation chart

Network

Data is organised like a graph: a record can be linked to many parents and many children.

e.g. a road or telephone network

Relational

Data is organised into tables called relations, linked to each other through common values (keys).

★  The model used by MySQL, Oracle and most DBMS today — our focus

Object-Oriented

Data is stored as objects that bundle together values and the operations that act on them.

e.g. complex multimedia or design data

Tricky: Degree vs Cardinality

GOTCHA

Students most often swap these two. Columns = degree, rows = cardinality:

Table with 6 columns

and 40 rows

→  Degree 6, Cardinality 40

Degree counts columns (attributes); cardinality counts rows (tuples).

5 columns, 1 header row

and 20 data rows

→  Degree 5, Cardinality 20

The header row holds attribute names — it is not a tuple, so it is never counted.

4 attributes, 30 tuples

then insert 5 new rows

→  Degree 4, Cardinality 35

Adding rows changes only the cardinality — the degree stays exactly the same.

Properties of a Relation

PROPERTIES

●Each attribute has a unique name within the relation

●All values in an attribute come from the same domain

●Every value is atomic — one single, indivisible value per cell

●No two tuples are identical — duplicate rows are not allowed

●The order of tuples and of attributes does not matter

Foreign Key — Rules

FK RULES

●Each foreign-key value must match an existing primary-key value in the referenced relation — or be NULL

●Foreign-key values CAN repeat: many teachers can belong to one department

●A relation may have more than one foreign key

●The DBMS rejects a value that has no match — this protects the links between relations (referential integrity)

TRY IT: INSERT INTO TEACHER

Teacher with DeptID = D2

✗  Rejected — no department D9

Teacher with DeptID = NULL

✓  Allowed — no department assigned yet

Rapid Fire: Common Exam Traps

TRAPS

Four quick questions that trip up almost every class:

Table with 8 columns

and 25 rows

→  Degree = 8

Degree is the number of attributes (columns), never the number of rows.

Can a primary key

contain NULL?

✗  No

A primary key must be unique AND non-null — every tuple needs a real identifier.

Can two tuples in a

relation be identical?

✗  No

A relation is a set of tuples, so duplicate tuples are not allowed — keys prevent them.

A relation has 3 candidate

keys. How many alternate keys?

→  2

Alternate keys = candidate keys − primary key = 3 − 1 = 2.

1

A database is an organised collection of related data; a DBMS manages it and fixes the file system's problems
